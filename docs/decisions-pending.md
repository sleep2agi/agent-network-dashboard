### 为什么方案 A 我停在这里（不自行实施）

```
1) 争用只在"线上 Hub 串行 + 8–10 路并发"时出现；本地 3101 的首屏本来就是 1.6–2.4s，
   本地无法复现线上争用 ⇒ **无法在发布前验证效果**。
2) 这是改全局首屏取数（影响所有页面）。按本项目的纪律：
   "不能先验证的全局改动不上线"。
3) 唯一能验证的方式是先发布再测，一旦不达标就要回滚一次全局改动 —— 代价高于收益。
⇒ 需要你确认承担"先发后测"的方式，或提供可复现争用的环境（例如让本地也指向同一 Hub 并发路径）。
   两者任一到位，我按上面 5 步执行。
```
