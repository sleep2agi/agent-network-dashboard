# 军团 3D 中心区方案（供设计师选，2026-11-12）

> 背景：`.499` 试过"圆心加两行规模文字"，出图后当场否掉——文字与「军团」标签、
> 左右部门盘互相叠压（证据 `evidence/legion-3d-499-core/desktop.png`）。
> 结论不是"不该加信息"，而是**中心的空地没有为信息留出版面**。
> 本文给出三个方案，都带可测判据与成本，选一个再实现。

## 现状（`.507`）

```
圆心：仅 N 徽记 + 「军团」标签；核心环半径约 26px
周围：8 个部门盘（半径约 20px）分布在同一环上，最近的一个距核心约 40px
规模信息：只在页眉（14 个部门 · 9 名成员 · 351 个 Agent）
```

## 方案 A：核心环放大（信息进环内）

- 核心环半径按画布自适应放大（约 ×1.6，桌面约 42px、窄屏约 30px）；
- 环内两行：`351` / `Agent`（或 `351 Agent` + `14 部门`），字号随半径缩放；
- 部门盘位置不动。

**判据**
| 项 | 要求 |
|---|---|
| 文字与部门盘/「军团」标签的矩形相交 | 0 |
| 中心区域可读性 | 42px 环内文字 ≥11px，对比度 ≥ 4.5:1 |
| 帧率 | 与 `.507` 同档（纯文字绘制） |

**成本**：1.5–2 h（含 20 套验收）　**风险**：低（只放大核心与加文字）

## 方案 B：把信息移出中心（中心保持纯光）

- 中心不加任何文字/刻度；
- 规模信息改为画布左上角的**固定信息卡**（半透明底、两行、随主题变色）；
- 好处：中心继续保持"光井"的空灵感，信息可读性最稳（不参与 3D 变换）。

**判据**
| 项 | 要求 |
|---|---|
| 信息卡与页眉统计行/工具栏的矩形相交 | 0（窄屏需另行验，参考 `.506` 的 HUD 处理） |
| 信息卡不随相机旋转/缩放变化 | 旋转一圈截 4 帧，位置与尺寸不变 |
| 帧率 | 同档 |

**成本**：1–1.5 h　**风险**：低

## 方案 C：中心做成"徽章"（刻度环，不加文字）

- 沿核心环外缘画一圈分段弧：每段代表一个部门，按状态着色（沿用现有状态色）；
- 弧长按部门人数加权，形成"军团徽章"的语义；
- 不新增文字、不新增色相。

**判据**
| 项 | 要求 |
|---|---|
| 弧段数与部门数一致 | 14 段（当前编制） |
| 弧段与部门盘相交 | 0 |
| 与「层级只靠明度」是否冲突 | **不冲突**：弧段用同一状态色，不引入新色相 |

**成本**：2–2.5 h　**风险**：中（弧段与核心光井叠加时容易糊，需要调透明度）

## 三案对比

| | 信息密度 | 观感风险 | 成本 | 需要设计决策 |
|---|---|---|---|---|
| A | 最高（数字进中心） | 中（放大核心会挤压部门盘） | 1.5–2 h | 是（是否放大核心） |
| B | 中（信息在角落） | 最低 | 1–1.5 h | 否（只是位置） |
| C | 中（语义化刻度） | 中高（易糊） | 2–2.5 h | 是（徽章语义） |

## 共同前提（无论选哪个）

```
1. 都用 ?debug=1 的 labelMargin / groupPointDelta 与 ?perf=1 的边距做回归
2. 一版只做一个方案，避免"两个变量同时变"导致无法归因
3. 若出图后与部门盘叠压（像 .499 那样），**当场否掉**，不进入验收
```

## 补充事实（2026-11-12 核对代码后修正 B 案的范围）

```
「导出 PNG」**已经自带**标题栏 + 计数 + 图例 + 导出时间（`exportPng` 里画 head/foot 两条），
⇒ 静态图已经能自解释，"信息移出中心"对 PNG 是重复的

真正缺的是**录屏（WebM）**：那条路径只把主画布等比放进 16:9 画幅，
没有页眉/计数/图例（DOM 不进画面）
⇒ B 案的真实价值 = 给录屏补一行规模说明，而不是"把中心信息挪走"
```

**修正后的 B 案**：仅在录屏时于画幅左下角补一行
`{agents} Agent · {groups} 部门 · {people} 成员`（字号随画幅高度缩放）。
判据：录屏产物左下角存在该文字区域；正常浏览时**不出现**（避免与页眉重复）。

## A 案已实现为变体 `?core=big`（`.511`）· 归因修正

`.499` 把"环内放数字失败"归因为"核心环太小"。`.511` 把核心放大 1.6× 重做，
**依然失败** —— 两稿都失败才定位到真正原因：

```
AN 徽记绘制尺寸 = radius × 1.25
⇒ 放大半径时徽记同比放大，中心可用版面几乎不变
⇒ 真正的占版者是徽记，不是环半径
```

据此把徽记缩到 0.64× 并上移 0.26r，两行数字才完整落入环内。

| 稿 | 环内排版 | 实测问题 |
|---|---|---|
| 一稿 | 14px / 基线 +0.52r | 第二行被徽记压住，字形残缺 |
| 二稿 | 11px / +0.50r | 第二行被核心底部描边切掉半个字高 |
| 三稿 | 10.5px / +0.34r + 徽记 0.64× 上移 0.26r | 两行完整 |

```
读数（桌面 1440 / 窄屏 390）：默认 36.6 / 15.5px，变体 57.3 / 24.7px；
labelMargin 默认 132，变体 135 / 41 —— 放大核心没有挤压部门标签。
窄屏 24.7px < 26px 阈值 ⇒ 变体在手机上自动不画数字。
判据教训：1440 全图看不出第二行被切，必须把核心区放大 4 倍再看。
```

现状：变体已上线，**默认观感不变**；是否转为默认，取决于"AN 徽记能否让位"这一设计判断。
