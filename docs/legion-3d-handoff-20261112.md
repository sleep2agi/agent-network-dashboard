## 3. 取景抖动 ±7%：七个假设，全部有数据

```
1 编制/状态数据在变         → agents / offline / 部门 / 成员 恒定 → 否
2 安全区测量不稳            → safeBounds 恒为 24,135,1208,864 → 否
3 标签矩形并入取景（反馈环） → 撤销后仍抖 → 否
4 取景复用"当前帧投影"      → 改固定参考焦距后仍抖 → 否
5 自转 yaw（相对采样）      → 8-yaw 并集后仍抖 → 否
6 固定绝对 yaw 采样         → 121/115/121/113 → 否
7 逐节点采样本身            → 改用环几何（旋转对称）→ **是**
```

结论：抖动的根因是「逐节点采样」，不是某个参数。环是旋转对称的圆，
投影包围盒与 yaw 无关 ⇒ 用环轨迹 + 固定外扩即可，既确定又更省。

## 判据的坑（记录两条，避免误报）

```
1) 元素矩形相交 ≠ 视觉碰撞
   桌面的 toolbar 是 flex 容器、宽度横跨整行；HUD 在左上、按钮在右侧
   ⇒ 用「容器矩形」判相交会误报 true（实测 HUD 到 x≈680 结束，按钮从 x≈890 开始）
   正确做法：与「容器内实际子元素的外接框」比较，或用截图核对

2) 采样过早 ≠ 状态不稳
   军团 3D 有入场动效与分批数据；必须等 introState='done' 且 edgeEnergy>0 再读读数
   否则会读到 zoom=112（默认值）或 edge=0.0（连线未画），看起来像"又抖了"
```
