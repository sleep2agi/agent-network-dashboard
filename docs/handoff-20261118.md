## 4. 发版链（每次约 2.5 小时；确认目标后再跑）

```bash
python3 deploy/next-release.py --from <live> --to <new> --sha <完整sha>
python3 deploy/run-<new>-final-acceptance.py
python3 deploy/collect-<new>-main-ci.py <完整sha>     # 必须带 SHA 参数
python3 deploy/publish-<new>.py --source releases/preview.<new>-<短sha> --yes
bash deploy/post-release-check.sh <完整sha>
bash deploy/health-all.sh && bash deploy/legion-verify-all.sh
```

⚠️ 五条硬规矩（今天各踩过一次）：

0. **改完再跑门**：改 → tsc → test → gates → oss → 提交。任何一步跑在改动之前都不算数
   （曾出现：加完测试文件没重跑 tsc，本地全绿、CI 红在 TS7006）。
0b. **提交路径**：功能/修复走 `try/*` 分支 + `git merge --no-ff`；main 只允许
   `chore: release` / `docs:` / `Merge` —— pre-commit 会拦，别用 `--no-verify` 绕。
1. 门失败时**直取退出码**（`cmd > log; rc=$?`），不要用 `cmd | tail && next` —— 管道会吃掉退出码。
2. 同一版本号重跑前，必须清掉 `*-<N>` 套件产物目录，否则验收会因"陈旧产物"拒跑。
3. 修完代码产生新提交后，旧 SHA 的验收脚本作废：删掉重新生成，不要复用。
