## 6. `/messages` 长页复核（`.524` 线上）——B 案其实已经实现了

```
实测（390×844）：docH 18,841 · 消息条目 31 条（30 条 + 「Load earlier messages」）
点击「↑ Load earlier messages」→ 61 条 / docH 38,647   ⇒ 分批本来就是 30 条/批
```

结论：`/messages` 的 19k px 不是"没分批"，而是**30 条长消息本身很高**（单条约 600px）。
因此：
- 原「B 首屏条数」选项等于改 `HISTORY_PAGE`（30 → 更小），收益有限且会让用户多滚一次；
- 真正能压高度的只有「A 长消息折叠」，但那是**隐藏内容**的产品决定，需产品/设计拍板；
- 现状记为：已分批、内容驱动、不改。
