## 军团 3D 浅色主题对比（2026-11-16 取证，结论：需设计选方向）

| 主题 | 暗像素占比 <180 / <200 / <220 | 结论 |
|---|---|---|
| 深色 cyber | 99.59% / 99.82% / 99.95% | 达标（默认主题） |
| **浅色 light** | **2.04% / 2.55% / 5.06%** | 画布 97.9% 像素亮度 >180，节点/点阵在近白底上几乎看不见 |

试过并回退的方案（同一探针 A/B，线上 `.584` vs 本地）：
```
描边压暗 35% + 线宽 ×1.2~1.3（三处分支都试过）→ 浅色暗像素占比 2.04% → 2.10%（+0.06pp）
⇒ 收益小于测量噪声，已 git checkout 回退，不留无收益 diff
```

可选方向（都需要设计确认，都会改变"浅色下军团长什么样"）：
```
A 浅色主题给画布加极浅中性底（如 #f2f4f7），提高全局对比
   —— 注意：不能靠加大 accent 渐变透明度，代码注释已记录"会把整张图洗成一片绿"
B 浅色主题把节点半径放大 1.3–1.5×（点阵更实，不改配色）
C 浅色主题改"墨线"绘制：节点用压暗 45% 的状态色实心 + 无白芯（像印在纸上）
   —— 观感变化最大，但对比最强；需要看两版对比图再定
```
三者都不影响深色主题（默认）；C 的方案本质是"浅色下换一套绘制语言"。

## 门的三种结局：PASS / DEGRADED / FAIL（2026-11-16 定规）

```
PASS     判据成立，样本有效
DEGRADED 判据没成立也没被推翻 —— **样本不可信**（负载高、画面在动、按钮没点上、读不到内部状态）
         退出码 3；health-all 记为 DEGRADED，不计红，但必须打印原因
FAIL     样本有效且判据不成立 —— 页面/产品真的不对
         退出码 1

为什么要分三档（今天的实例）：
  legion-canvas-text 在 16 门并行跑批时报 1.4:1（远低于 4.0 下限）；
  单跑 1 次 → 6.18 PASS；连跑 5 次 → 5/5 PASS。
  真因是探针自己的前提被破坏：它要求"先关自转、画面静止再采样"（.536 的教训），
  并行负载下那个点击没生效 ⇒ 读到上一帧位置 ⇒ 假低值。
  ⇒ 这类不是"页面坏了"，报 FAIL 会逼下一个人去改渲染；报 PASS 又等于放过了取样缺陷。
  所以：显式确认自转已关，关不掉就记 sample-invalid → DEGRADED，并打印"哪一格、为什么"。
```

## 两条原理（今日沉淀，来自实际返工）

```
一、「手段窄」是代码属性，「影响窄」是几何属性，两者不自动相等
   · A 案只改一行（部门环外推 2%），却把 1.3 层距下的叠压对数从 6 推到 18
   · ⇒ 窄改也必须全量复测，不能因为"只动一处"就跳过判据

二、「重复的记录」比「缺失的记录」更糟
   · 缺一句是"不知道"，两段互相矛盾是"知道两个且无法判断哪个是真的"
   · `.502` 因此不发布：代码通过 20 套验收，但 CHANGELOG 出现两段 .502 说明
   · ⇒ 版本号冲突时，宁可重做一版把记录合并，也不带着矛盾上线
```

## 几何对照口径（2026-11-11 新增，工具：evidence/probes/geom-compare.mjs）

```
判决顺序：先锁集合，再比坐标
① 集合不同 ⇒ INVALID（exit 2），列出 only-A / only-B，**不输出位移数字**
② 集合同 ⇒ 位移 >0.5px 的节点数 + 最大位移（exit 0 = PASS）
③ --allow-subset --reason '…' ⇒ 用共同子集再算，结果标 SUBSET=true
```
```
实测（真实发生过的一次误读）：
A. geom-488 vs geom-489（跨时刻）：only-A 1 / only-B 1 ⇒ INVALID
B. same-488 vs same-489（同时刻同集合）：位移 0/80 · 最大 0px ⇒ PASS
C. A 两份 + --allow-subset：SUBSET=true · 共同 79 · 位移 60 · 最大 65.4px
⇒ 与设计师独立算出的 60 / 65.4 完全一致，说明"61/80 位移"确由 1 个 agent 换人引起
```
